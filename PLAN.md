# Interpreter — Modernization Plan

Status: **Phase 1 + Phase 2 + Phase 3 + Phase 4 complete (2026-08-26).**

## Current state

Facts that hold *now*. Issues/gotchas live in the phase item that resolves them.

**Product decisions** (stand until superseded):

- **Local models only** — no cloud STT/translation, no API keys, ever.
- **App form (Phase 4)**: local desktop GUI via **PySide6 (Qt)** — native AppKit windows, no webview in the chain — over the same package. Originally built on **pywebview** (native window + HTML/JS) and switched (2026-08-25) because the WKWebView window tripped the host's external Dell display link (flicker when the window was moved onto it, even fully idle — a webview compositing artifact). Native macOS/iOS via Swift + sherpa-onnx bindings stays parked: an iOS port would rewrite the engine natively regardless, so the throwaway part is the window, not the engine. App Store/notarization ($99/yr) is a distribution-phase decision only — running the app locally costs nothing.
- **Minimal feature scope** — models are internal per-task picks, never user-facing. User config = `mode` (`listen`/`dictate`) + `translate` bool (listen only — **dictate never translates**) + scope only: `listen` is en-only by design; `dictate` defaults to mixed zh/en with an `--en` flag for English-only. Full flag surface: `listen [--no-translate]`, `dictate [--en]`. **Speaker ID (listen)**: auto-tags `self`/`other` — always on, no opt-out flag, no enrollment step; segments that can't be confidently matched are flagged `[?]` (never silently mislabeled). Dev knobs stay library-only (`input_path` + `max_segment_duration` for the benchmark/replay harness); default segment cap **4.0 s**.
- **≤1B parameter policy; no CC-BY-NC-or-stricter weights; no auth-gated downloads.**
- **Session files**: listen/dictate always record to `data/listen/` / `data/dictate/` as FLAC (int16) with the plain-text transcript as a sibling `.txt` (listen: per-chunk lines with timestamp/speaker + translations; dictate: the clean text). **Resume (Phase 4)**: a session can be resumed — new audio and transcript lines append to its `.flac`/`.txt`/`.styled` (the old audio is read before the merged write; an empty resumed session leaves the files untouched). **Editing + rename (Phase 4)**: a saved transcript can be hand-edited in the GUI — **autosave** writes it back to the session's `.txt` ~0.8 s after the last keystroke (debounced; also flushed whenever the pane's content is about to be replaced: selection/mode change, start, window close). **Per-word confidence colors survive edits**: the pane's rich text is converted back to the engine's ANSI format (`_html_to_styled`) and stored in the `.styled` twin — Qt preserves character formatting as the user types, so unchanged words keep their model colors and edited text inherits the formatting at the cursor; UI meta colors (timestamps, speaker tags, translations) drop to plain. Sessions can be **renamed** in the sidebar (double-click; the `.flac`/`.txt`/`.styled` files all rename with the entry; invalid or colliding names revert; renames are locked while a session runs).
- **Container is the benchmark environment** (Linux, 8 GB/8 cores; M4 host numbers are reference only). Entry point is the CLI: `uv run python -m interpreter <listen|dictate|benchmark>`.

**Startup**: VAD / Translator / STT load **concurrently** (`RealTimeTranscribe._load_models` — independent model stacks, startup waits for the slowest not the sum; worker failures re-raise in the main thread). Silero loads via **direct `torch.jit.load` of the cached `silero_vad.pt`** (skips `torch.hub`'s repo clone/import — also avoids the torchaudio import); transformers uses **`local_files_only=True`** with a download fallback for first use. CLI prints a loading status line.

**Model verdicts** (60-sample container pass; **full records: `_archive/benchmark_transcribe.md`, `_archive/benchmark_translate.md`, `_archive/benchmark_speaker.md`**):

- listen / en-only → **Parakeet Unified en 0.6B offline mode** (sherpa-onnx int8, since 2026-08-25); dictate / multilingual → **SenseVoiceSmall** (only true zh↔en code-switcher); translate → **opus-mt-en-zh** (only backend; LLM quality mode dropped).
- whisper.cpp / Moonshine **dropped from the product**; the whispercpp baseline is superseded (pre-drop harness at commit `59e91d7`).
- **TDT removed from the registries (2026-08-25)**: `parakeet-tdt-0.6b-v2` (Phase 1 en-only winner, listen's model until the Unified switch) and `parakeet-tdt-0.6b-v3` — zero product use once Unified won (better WER at every segment cap, far more graceful short-chunk degradation, comparable RTF); removed from `MODEL_SPECS`/`_MODEL_FILES`/`available_models()`, weights deleted. Their results JSONs stay in `data/benchmark/transcribe/results/` so merged harness tables keep the historical baselines.
- **Speaker ID (listen) → WeSpeaker `wespeaker_en_voxceleb_resnet34`** (en, CC-BY-4.0): probe top-1 100% / EER 1.6% @ 0.74 on a 14-speaker LibriSpeech dev-clean subset. `wespeaker_en_voxceleb_CAM++` **dropped** (EER 39% — poor discrimination); **zh speaker ID dropped** — listen is en-only.
- **No true streaming on the container (probe 2026-08-25)**: sherpa-onnx 1.13.6 + onnxruntime 1.29.0 streaming exports (int8 Unified) measured 0.096 WER @560 ms / RTF 1.96 and 0.141 @240 ms / RTF 3.69 vs the windowed engine's best 0.114 @4 s cap / RTF 0.041 — not real-time on the container, so listen keeps the windowed engine with **Unified offline**. True streaming (0.096 @560 ms) stays a **faster-host option — left parked in Phase 4** (M4-class RTF ~0.11–0.2, strictly better: 0.096 final + chunk-cadence partials); Unified owns offline + streaming modes in one model.

**Architecture** (`src/interpreter/transcribe.py`):

- `RealTimeTranscribe`: Silero VAD → ring buffer → 3 worker threads (VAD → STT → translate); `max_segment_duration` (4.0 s) caps segments. **Adaptive stability-window re-decode**: each new segment re-decodes the whole window so the newest utterance gets predecessor context; once earlier text stops changing (`_stable_prefix` — word-boundary check for en, char-prefix for CJK), the window commits to `committed_chunks` and slides forward — the newest segment's display baseline is its portion of the windowed decode (the safe `_strip_prefix` tail), with a standalone decode only as a fallback for unstable windows; an empty baseline is kept, never reset away. Window cost is bounded by `max_window_seconds` 8 s / `max_window_segments` 3. **Live display runs in the terminal alternate screen** (`\x1b[?1049h`, clear-and-reprint per update — cursor-up/erase-line redraws leaked escape sequences + blank lines into macOS Terminal scrollback). `clean=True` (dictate CLI) renders one flowing line — per-word confidence colored when the STT exposes token scores (en-only/parakeet), plain otherwise (mixed/SenseVoice has none; zh: space-only separation; en: `.` per chunk — SenseVoice emits no punctuation) + a final `Transcript:` block to copy; listen keeps colored + timestamped + compute-time committed lines, a live partial, and **live translation of the current window** (latest-wins stale-skip; committed chunks reuse it). `evaluate()` reports WER for whitespace-segmented (en) text; CJK/mixed reports CER only (WER is meaningless on unsegmented zh).
- STT = sherpa-onnx int8 only: `sensevoicesmall` (default; mixed zh/en/dictate), `parakeet-unified-en-0.6b` (en-only/listen, offline mode). Parakeet colors per word; SenseVoice output stays uncolored (no per-token scores in sherpa-onnx 1.13.0 — documented limitation; **2026-08-26**: `_format_transcript`'s fallback that colored score-less segments uniform green was removed — styled is colored only where real per-token scores exist). **Dictate color coding (2026-08-26)**: the clean rendering uses the styled twins (`_flowing_styled_parts`) whenever the snapshot carries `\x1b[38;2;…m` confidence colors (`_has_confidence_colors`) — so `dictate --en` (parakeet) and the GUI's English-only dictate show per-word confidence, mixed dictate stays plain. **SenseVoice emits English in ALL CAPS (model artifact)** — `SpeechToText.extract_text` sentence-cases it for sensevoicesmall (live lines, final transcript, and evaluate reference); parakeet already outputs natural case and is untouched.
- Translate = `opus-mt-en-zh` (deterministic, ~1.2 s/sentence, en→zh).
- **Speaker (listen only)** — `speaker.py` `SpeakerAssigner`: WeSpeaker en extractor + an online auto-expanding registry (no enrollment; first voice = `self`, second = `other`). Loaded concurrently with VAD/STT/translator in `RealTimeTranscribe._load_models`; `_transcription_worker` **embeds the RAW segment** (noise-reduced audio compresses the embedding space and merges distinct voices) and `_ingest_segment` tags each committed chunk; listen lines render `[self]` / `[other]`, `[?]` for ambiguous matches. **Relative acceptance** — no fixed threshold (the same device voice measured 0.76–0.79 vs the user in one session but 0.84–0.87 in another): a segment is tagged when its similarity clears that cluster's own measured internal consistency (`_accept_threshold`: within `CONFIDENCE_DELTA` 0.05 of the cluster's mean member similarity, floored at `CONFIDENT_THRESHOLD` 0.84; `EARLY_CONFIDENT_THRESHOLD` 0.89 binds until the cluster has absorbed TWO members); a new speaker starts below the bar minus `NEW_SPEAKER_MARGIN` 0.15; in between → `[?]`, absorbed into **no** centroid. **kNN "looking back" window**: scored by MAX cosine to each speaker's KNN_WINDOW (6) most recent member embeddings, not the centroid (centroid averaging blends the shared mic channel and inflates cross-speaker similarity). **Gray-zone promotion**: buffered `[?]` embeddings promote to a named speaker when they form a tight cluster (≥3 segments, mean pairwise ≥ 0.85 with every member ≥ 0.80) whose similarity to every existing speaker stays below that speaker's own bar; a promotion **retroactively relabels** earlier `[?]` chunks only when the chunk belongs entirely to the promoted cluster (`_relabel_promoted`) — one speaker's words are never shown under another's label. Transcription text is BY CONSTRUCTION identical with/without speaker ID (the assigner feeds only display tags). **Per-speaker windows**: `speaker_changed` commits the window when the newest segment's assignment differs from the window's — a line only appends the right speaker's speech. **MAX_SPEAKERS = 2** ("just self and other"): the new-speaker path and promotion refuse once two speakers are named; further distinct segments stay `[?]` (all recorded sessions yield exactly `self` + `other`). **Margin rescue**: with two speakers, a segment just below its best speaker's bar (within 0.03) is accepted when it beats every other speaker by ≥ 0.08. **New-speaker quality gate**: a new speaker is created only for real speech (≥ `MIN_NEW_SPEAKER_DURATION_S` 1.0 s and ≥ `MIN_NEW_SPEAKER_RMS` 0.03); gated blips buffer as uncertain. Promotion preserves the pending buffer's non-promoted segments (clearing would wipe a second gray-zone voice's accumulated evidence).
- Weights shared with the benchmark under `data/benchmark/transcribe/models/` (anonymous HF download). App form: **PySide6 (Qt)** — decided and shipped in Phase 4.
- **Rendering is decoupled from the engine (Phase 4)**: `RealTimeTranscribe` renders via `BaseRenderer` (`begin`/`render`/`end`) over immutable `TranscriptSnapshot`s (chunks + live window + header, built under `display_lock`). Default = `TerminalRenderer` (reproduces the CLI output byte-identical, alternate-screen + dim `[?]` live inside the renderer); GUI = `SnapshotStore` (keeps the latest snapshot for the JS pull loop). `quiet=True` suppresses end-of-session prints; public `stop()` flips `running` only — `run()` finalizes and writes session files after the mic loop exits, so no audio callback can race the file write.
- **GUI (`src/interpreter/app.py`, `python -m interpreter app`)**: **PySide6 (Qt)** native window. `SessionController` owns engine threads, status and session history; the engine pushes immutable snapshots into a `SnapshotStore` (latest + version counter); a 150 ms QTimer on the main thread polls `pull()` and renders into widgets (no Qt code ever runs in engine threads). **Stop is non-blocking (2026-08-25)** — `stop()` only signals; joining the engine thread on the GUI thread hung the UI when Stop was clicked while models were still loading (`_launch` likewise no longer joins). The poll picks up the thread's own `stopped` status and refreshes. Listen: per-word confidence colors (the engine's ANSI `styled` parsed into Qt rich text), colored speaker tags, timestamps, translation lines, live window line; dictate: flowing text — per-word confidence colored when available (English-only → parakeet), plain in mixed (SenseVoice). Transcript pane: read-only while recording, editable once idle — edits **autosave** (debounced 0.8 s `textChanged` → `_flush_autosave`, flushed before the pane is replaced on selection change / mode change / start / window close; `save_transcript` is mode/path-guarded like delete). **Edits keep the per-word confidence colors, edited words render white (2026-08-26)**: the flush converts the pane's rich text back to the engine's ANSI format (`_html_to_styled` — Qt keeps character formatting through typing, so unchanged words keep their model colors; the fixed UI meta colors for timestamps/speakers/translations drop to plain, translation lines get the `    → ` indent back) and writes that to the `.styled` twin — re-selecting the session re-renders the edited text WITH its colors. Words that were **edited or added lose their color** (diffed against the text as loaded via `_edited_word_indices` / difflib SequenceMatcher) — they render white instead of inheriting the neighboring word's confidence color. **Session rename (2026-08-26)**: double-click a list entry to rename it — `rename_session` renames the FLAC/`.txt`/`.styled` files so the entry keeps matching disk (colliding/invalid names revert silently; edit triggers are disabled while a session runs — renaming would move the engine's files out from under it; the `itemChanged` noise from item creation during list rebuild is a no-op because the text equals the stored name). **Resume (2026-08-26)**: a **Resume** button (enabled for exactly one selected session; the list is mode-filtered so the mode always matches) records into the selected session's files — the engine merges the new audio into the existing FLAC and appends the new transcript lines; the old transcript renders as a read-only prefix above the live content while recording. **The poll renders snapshots only while `listening`** — after stop the pane is refreshed from the saved files, and a late final snapshot must not clobber that reload (gotcha found by the offscreen test: `_refresh_sessions` rebuilt the list with signals blocked, so no selection handler reloaded the pane after stop; fixed by explicitly reloading via `_session_selected` on refresh + gating `_render` to live status). **The sidebar follows the active recording (2026-08-26)**: the engine names the live session as soon as its thread starts (before any file exists), and `_poll` adds + selects it in the sidebar via `_track_live_session` — so on stop the just-recorded session stays selected and its transcript is shown, instead of the previously-selected session (operations on the placeholder item are safe: reveal/delete/drag-out/resume all re-check the files). **Gotcha (host report)**: `setCurrentItem` only ADDS to the selection in ExtendedSelection mode (needed for batch delete), so the previously-selected session stayed highlighted next to the live one — `_select_only` (clearSelection + setCurrentItem) is used everywhere the selection must be exclusive (`_track_live_session`, `_mode_changed`'s newest-session binding). **Stop flicker (host report)**: `_stop` used to rebuild the list while the engine's files don't exist yet (the live entry dropped, the poll re-added it, then the poll's stop refresh rebuilt once more — a visible double flicker). `_stop` no longer refreshes (the poll's single final refresh covers it), and `_refresh_sessions` suppresses repaints across the clear+repopulate (`setUpdatesEnabled(False)`) so the rebuild paints once. Sessions sidebar (QListWidget newest-first + detail pane) with **Reveal** (opens the session's folder in Finder with the file selected via `open -R` — no TCC permission needed) and **Delete** (multi-select via ExtendedSelection, no confirmation; **Playback/Export removed 2026-08-25** — Reveal covers both). The list (**`SessionList`** subclass) exposes the files as local file URLs in its drag mime data so sessions can be **dragged straight to Finder**. `delete_sessions` moves the FLAC + `.txt` to the **system trash in one batch** — Finder via `osascript` on macOS with a `~/.Trash` move fallback (TCC permission denied / Finder slow), freedesktop `$XDG_DATA_HOME/Trash` elsewhere, in `app.py` — no new dependency; guarded against bad modes/paths; delete runs in a background thread with a transient status message). **Double-click launch (2026-08-25)**: `scripts/make_app.sh` (host) builds a thin `dist/Interpreter.app` — launcher execs the host venv's `python -m interpreter app`, dock icon from `Interpreter.icns` (QPainter-drawn by `scripts/make_icon.py` into an iconset → `iconutil`), Qt window icon from `build/icon.png` when present. **The repo path is baked into the launcher at build time, so the bundle works from anywhere (e.g. `/Applications`)**; a walk-up from the bundle is the fallback for a moved repo; re-run `make_app.sh` after the repo moves or the icon changes. **Launcher failures are never silent: stderr goes to `~/Library/Logs/Interpreter.log`** (a Finder-launched app has no terminal — the earlier walk-up-only launcher failed silently in /Applications). Status label shows engine status only; the active models render **one line each with the FULL model id** in a small (10 pt) muted label under it (`stt: parakeet-unified-en-0.6b` / `translate: opus-mt-en-zh` / `speaker id: wespeaker_en_voxceleb_resnet34`) — clearly distinct from the status text; **font size is adjustable** (header `A [n pt]` spinbox, 10–22 pt, persisted in `QSettings`; scales the base app font + transcript (15 pt base) + models label; **Qt 6 gotcha: widgets with any stylesheet don't follow `QApplication.setFont` — buttons and the status label get their fonts set explicitly in `_font_size_changed`**). Listen/Dictate is a QSS-styled **segmented control** (slate track `#eef2f7`, selected segment filled **baby blue `#4f8cff`** with white text — matching the app icon — the unselected segment is clearly "off"; same height as Start/Stop: zero container margins, matching vertical padding); Start is the filled baby-blue primary (`_PRIMARY_BUTTON_QSS`), Stop/Reveal/Delete neutral white with blue tints (`_ACTION_BUTTON_QSS`). **App icon**: baby-blue gradient rounded square (`#4f8cff`→`#2f5fd0`) with a white chat bubble only (waveform bars removed 2026-08-25) and an 8% artwork margin so it matches neighbor dock-icon sizes. **Switched from pywebview (2026-08-25)**: the WKWebView window's compositing tripped the host's Dell display link (screen flicker when the window moved onto it, even idle, no session) — a webview artifact, not engine behavior; the engine/controller were untouched by the swap.

(b) Whole-screen flicker while dragging: root cause is the **WKWebView not being layer-backed** — non-layer-backed webviews redraw synchronously during macOS live window drags (Chromium does the same via `cr_setWantsLayer:YES`); pywebview's cocoa backend never sets it, so `main()` wraps `BrowserView.__init__` (a plain Python class) to call `setWantsLayer_(True)` right after the webview is created (no-op off macOS). **Gotcha (host crash)**: a first attempt replaced the `WebKitHost.initWithFrame_configuration_` class attribute — pyobjc re-dispatches a replaced selector through the class, so calling the old wrapper recursed (`RecursionError` at startup); the `__init__` wrap avoids selector replacement entirely. Also: `background_color` matches the page (default white flashed through), `pull()` suppresses snapshots while the window is dragged (`events.moved` hook, 250 ms pause), and the JS pull loop is change-guarded so steady state performs zero DOM writes. (c) `_launch` now reaps a finishing engine thread (status flips to "stopped" microseconds before the thread dies — a fast Start click used to be silently ignored) and flips status to `starting` **synchronously** — the new thread only reaches `loading` microseconds after `start()`, so waiters polled a stale `stopped` and thought the new session had already ended.
