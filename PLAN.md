# Interpreter — Modernization Plan

Status: **Phase 1 complete (2026-08-24) — Phase 2 next** (research done 2026-08-22; container pass 2026-08-23 + re-run 2026-08-24; model-selection conclusion in `docs/benchmark.md`; host pass dropped by policy; Mode B deferred).

## Current state

Facts that hold *now*. Issues/gotchas are not listed here — they live in the phase item that resolves them (below).

**Product decisions** (stand until superseded):

- **Local models only (2026-08-21)** — no cloud STT/translation, no API keys, ever. Online paths are a commodity (OpenAI itself ships `gpt-realtime-whisper` / `gpt-transcribe` / `gpt-realtime-translate`), so they add no differentiation and carry per-minute cost. The product's edge is the local bilingual zh↔en pair: privacy, offline, zero cost. Removed: deprecated OpenAI script, `openai_api_pricing.yaml`, `openai` dependency.
- **Language scope is a config, not a mode (2026-08-22).** Both `listen` and `dictate` support `en-only` and `multilingual` (zh/en mixed) variants; STT and translation are independently configurable per mode. **Translation must be fast** — target sub-second per segment: fast dedicated NMT by default, optional LLM quality mode.
- **No CC-BY-NC (or stricter) model weights in the product** (MIT repo): excludes NLLB-200 and Moonshine's non-English models; opus-mt / M2M100 / MADLAD-400 licenses are verified in Phase 1.
- **Entry point stays `transcribe.py` (2026-08-22)** — no rename for now; a `__main__.py` + argparse CLI (subcommands `listen|dictate|benchmark`) is deferred to the Phase 2 CLI item. Current `run()` → `evaluate()` in one command is known-temporary.
- **The container is the model filter (2026-08-23; upgraded 2026-08-24).** Benchmarking runs only in the Linux container (**now 8 GB RAM / 8 cores**, was 4 GB/4 cores), one model per subprocess; a model that does not fit (OOM, exit −9/137) is excluded from consideration — too big to fit is obviously too slow to matter. With the 8 GB budget the filter rarely trips; size/license policy exclusions dominate instead. No host benchmark pass; the M4 host numbers from 2026-08-23 are reference context only (`docs/benchmark.md`). Mode B (zh↔en dictation) is covered by synthesized mixed samples (AISHELL-1 + LibriSpeech); self-recorded dictation is a future validation, not a blocker.
- **≤1B parameter policy (2026-08-24).** Models larger than 1B parameters (published size) are out of benchmark scope: faster-whisper `large-v3` (1.55B) removed from the registry; Qwen3-ASR `1.7B` (removed 2026-08-23) subsumed; never-benchmarked candidates excluded by size: Cohere Transcribe (2B), FireRedASR-AED/-2-AED (1.1B), GLM-ASR-Nano (1.5B), Gemma 3n / TranslateGemma (gated, >1B effective), Kimi-Audio (7B). Ruling: published size counts — ARK-ASR-0.6B (0.6B decoder, ~1.2B end-to-end) is in, flagged in `docs/benchmark.md`. License exclusions stand: no CC-BY-NC or stricter — Canary-1b v1, NLLB-200, and MADLAD-400 (gated + CC-BY-NC → **dropped from the fast-NMT plan**). CC-BY-4.0 (Parakeet, Nemotron, Moonshine) is fine with attribution.
- **No auth-gated downloads (2026-08-24).** Models requiring authentication to download are excluded — the container has no credentials, and online/credentialed paths are out of scope by the 2026-08-21 decision. Excluded: Qwen3-MT-0.6B (gated on HF, no ModelScope mirror), Gemma 3n / TranslateGemma (manual license gate). Everything benchmarked downloads anonymously.

**Benchmark shortlist** (frozen 2026-08-22 — the research output; **the full model list, numbers, and per-model rationale live in `docs/benchmark.md`**):

- **en-only tier** (for `en-only` configs): Parakeet TDT 0.6B v2 via sherpa-onnx int8 (winner); Parakeet TDT 0.6B v3 (2026-08-24 addition — en non-upgrade over v2); Nemotron-3.5 ASR streaming 0.6B and Parakeet TDT-CTC 110M-en (2026-08-24 additions, not run — the sherpa-onnx `OnlineRecognizer` factories exist only on master); whisper.cpp `medium.en` and Moonshine v2 streaming-medium (shortlisted, then **dropped from the product 2026-08-24**).

- Excluded (why, in `docs/benchmark.md`): by the ≤1B policy — faster-whisper `large-v3`, Qwen3-ASR `1.7B` (also a broken transformers path), Cohere Transcribe, FireRedASR, GLM-ASR-Nano, Gemma 3n/TranslateGemma, Kimi-Audio; by license — Canary-1b, NLLB-200, MADLAD-400, omniASR; by auth-gated downloads — Qwen3-MT-0.6B, Gemma 3n/TranslateGemma; by data — Dolphin (en-deaf, zh-only specialist), whisper.cpp `medium.en` (dominated), Moonshine (weaker than Parakeet), Kitten/Zion, FireRedASR2-LLM, VoxCPM (TTS).
- **Verdicts (2026-08-24, 60-sample container pass; numbers in `docs/benchmark.md`):** listen/en-only → **Parakeet TDT 0.6B v2**; dictate/multilingual → **SenseVoiceSmall** (the only true zh↔en code-switcher; Qwen3-ASR `0.6B` is the closest alternative); the whispercpp baseline is **superseded — dominated on every axis, no config cell keeps it**.
- **Translation (2026-08-24):** translate is **opus-mt-en-zh only** (winner; M2M100-418M benchmarked behind it). The qwen3.5 `0.8b` LLM quality mode was **dropped 2026-08-24** (live dictation A/B: hallucinated content + a meaning-reversed error — "choose this model instead" → 换成另一种方式); the `ollama` dep + benchmark adapter were removed (product + harness). MADLAD-400 dropped (gated, CC-BY-NC); Qwen3-MT-0.6B excluded (auth-gated).

**Current architecture** (`src/interpreter/transcribe.py`):

- `RealTimeTranscribe`: Silero VAD (`torch.hub` → `snakers4/silero-vad`) feeds a ring buffer; three daemon threads consume queues for VAD → transcription → translation; `max_segment_duration` caps segment length.
- STT is `SpeechToText` (dispatch, 2026-08-24; **sherpa-onnx int8 only since 2026-08-24 — whisper.cpp and Moonshine both dropped completely**): **`sensevoice`** (sherpa int8) is the **product default** (interim single default until Phase 2 per-mode config — flipped 2026-08-24), **`parakeet-tdt-0.6b-v2`** (sherpa int8) is the en-only/listen option. Sherpa segments: the **transducer (parakeet)** colors per word via sherpa's per-token `ys_log_probs` (grouped in `sherpa_stt.py`'s `_word_probs_from_result`, 2026-08-24); **SenseVoice exposes no per-token scores in sherpa-onnx 1.13.0** — its output stays uncolored (uniform green), a documented limitation (docs/benchmark.md). Weights: shared with the benchmark (`data/benchmark/transcribe/models/`, anonymous HF download).
- Translate is `Translator` (2026-08-24): **`opus-mt-en-zh` (Helsinki-NLP seq2seq) — the only backend** — best BLEU on the benchmark corpus (33.59); deterministic, ~1.2 s/sentence, single pair en→zh. The qwen3.5 `0.8b` LLM quality mode (via ollama) was **dropped 2026-08-24** (see "Translation" above); no ollama server required, `ollama` dep removed.
- **Benchmark baselines (historical measurement anchors; superseded by the Phase 1 conclusion 2026-08-24):** transcribe = `whispercpp-large-v3-turbo-q5_0`; translate = `ollama-qwen3.5-0.8b`. **whisper.cpp and Moonshine were dropped from the product completely 2026-08-24** (no `whispercpp.py` / `moonshine_stt.py`, no dispatch entries, `pywhispercpp` / `moonshine-voice` deps removed; the pre-drop harness survives at commit `59e91d7` — whisper.cpp re-runnable from there, Moonshine's dep was never committed — rationale and numbers in `docs/benchmark.md`). **The interim product default is `sensevoice` + `opus-mt-en-zh`** (flipped 2026-08-24 — SenseVoice is the only true code-switcher and the fastest+lightest model in the benchmark; en-only accuracy takes a small hit vs Parakeet in the interim) until Phase 2 wires per-mode config (listen → Parakeet v2 / dictate → SenseVoiceSmall; the streaming path = a sherpa-onnx `OnlineRecognizer` probe of Parakeet).
- `RealTimeTranscribe.evaluate()` computes WER/CER (jiwer) vs a full-file reference; only meaningful when `audio_file_path` is set.
- Final product form (Python pkg + local web UI vs native macOS/iOS app) is **undecided** — Phase 3 decides. Recommended default: local FastAPI web UI over the same package; native macOS/iOS later via sherpa-onnx / Moonshine native bindings stays open.

**Benchmark environment** (facts, 2026-08-23; upgraded 2026-08-24):

- **Container (agent) is the benchmark environment** — Linux aarch64, **8 cores, 8 GB RAM** (upgraded 2026-08-24 from 4 cores/4 GB), Python 3.14.7. - **Notes merged into this phase** (resolved when the phase is checked off):
  - Threading finding: threads run concurrently (total ≈ max of per-thread times, not the sum). `RealTimeTranscribe` already runs 3 worker threads (VAD → STT → translate), but **transcription is single-threaded**: one `_transcription_worker` serially drains `q_for_transcription`, and the sherpa recognizer blocks per segment. If STT time > segment duration, the queue backlogs and latency grows. (whisper.cpp, the original subject of this finding, was dropped 2026-08-24 — the finding is now about the sherpa backends.) Candidate refinements to evaluate during the port: (a) instrument first — re-enable timing logs + queue-depth counters to measure the backlog; (b) parallel transcription workers (one `SherpaStt` per worker); (c) `num_threads` (already a `SherpaStt` init arg, `sherpa_stt.py`) to parallelize within a segment; (d) split `process_audio_segment` (noisereduce) into its own worker stage.
