# Interpreter — Modernization Plan

Status: **Phase 1 + Phase 2 + Phase 3 complete (2026-08-25). Phase 4 (app form) next.**

## Current state

Facts that hold *now*. Issues/gotchas live in the phase item that resolves them.

**Product decisions** (stand until superseded):

- **Local models only** — no cloud STT/translation, no API keys, ever.
- **Minimal feature scope (2026-08-24)** — models are internal per-task picks, never user-facing. User config = `mode` (`listen`/`dictate`) + `translate` bool (listen only — **dictate never translates**, CLI `--translate` removed 2026-08-25) + scope only: `listen` is en-only by design; `dictate` defaults to mixed zh/en with an **`--en`** flag for English-only (2026-08-25 — replaced the old `--language en-only|mixed` choice; the full flag surface is now just `listen [--no-translate]`, `dictate [--en]`). **Speaker ID (2026-08-24)**: listen auto-tags speakers (`self`/`other`/`speaker N`), always on — no opt-out flag, no enrollment step, no extra config. Segments that can't be confidently matched are flagged `[?]` (never silently mislabeled) — see the threshold band below. (The dev knobs `--max-segment-duration` / `--input-file` were removed from the CLI 2026-08-25; the library keeps `input_path` + `max_segment_duration` for the benchmark/replay harness. Default segment cap **4.0 s (2026-08-25, was 5.0)** — free latency win on the sweep: Unified WER 0.114 @4 s vs 0.115 @5 s.)
- **≤1B parameter policy; no CC-BY-NC-or-stricter weights; no auth-gated downloads.**
- **Session files (2026-08-25)**: listen/dictate always record to `data/listen/` / `data/dictate/` as FLAC (int16 — ~9x smaller than the old WAV) with the plain-text transcript as a sibling `.txt` (listen: per-chunk lines with timestamp/speaker + translations; dictate: the clean text). `--audio-file` removed — paths are fixed defaults.
- **Container is the benchmark environment** (Linux, 8 GB/8 cores; M4 host numbers are reference only). Entry point is the CLI: `uv run python -m interpreter <listen|dictate|benchmark>` (since Phase 2, 2026-08-24).

**Startup**: VAD / Translator / STT load **concurrently** (`RealTimeTranscribe._load_models` — independent model stacks, startup waits for the slowest not the sum; worker failures re-raise in the main thread). Silero loads via **direct `torch.jit.load` of the cached `silero_vad.pt`** (skips `torch.hub`'s repo clone/import — also avoids the torchaudio import); transformers uses **`local_files_only=True`** with a download fallback for first use. CLI prints a loading status line.

**Model verdicts** (2026-08-24, 60-sample container pass; **full record: `_archive/benchmark_transcribe.md`**):

- listen / en-only → **Parakeet Unified en 0.6B offline mode** (since 2026-08-25 — supersedes TDT 0.6B v2, removed from the registries; see below); dictate / multilingual → **SenseVoiceSmall** (only true zh↔en code-switcher); translate → **opus-mt-en-zh** (only backend; LLM quality mode dropped; record: `_archive/benchmark_translate.md`).
- whisper.cpp / Moonshine **dropped from the product**; the whispercpp baseline is superseded (pre-drop harness at commit `59e91d7`).
- **Removed from the registries (2026-08-25): `parakeet-tdt-0.6b-v2`** — the Phase 1 en-only winner (listen's model until 2026-08-25) had zero product use after the Unified switch, so it was removed from `MODEL_SPECS`, `_MODEL_FILES` and `available_models()`; weights deleted. **Why removed**: Unified beats it on every axis measured — en-only WER 0.126 vs 0.148 (full 60-sample set), human-ref WER 0.115 vs 0.169 @5 s cap (Phase 3 streaming item), RTF comparable (0.041 vs 0.038) — and its chunked inference collapses below ~2 s (22.83 @ 1.12 s on the leaderboard), so it had no path to streaming. **Its existence is documented in**: `_archive/benchmark_transcribe.md` (Phase 1 record), the Phase 3 streaming item (sweep tables), and its benchmark results JSON kept at `data/benchmark/transcribe/results/parakeet-tdt-0.6b-v2.json` so merged harness tables still show the historical baseline.
- **Speaker ID (listen) → WeSpeaker `wespeaker_en_voxceleb_resnet34`** (en, CC-BY-4.0): probe top-1 100% / EER 1.6% @ similarity 0.74 on a 14-speaker LibriSpeech dev-clean subset (**full record: `_archive/benchmark_speaker.md`**). `wespeaker_en_voxceleb_CAM++` **dropped** (EER 39% — poor discrimination, verified not a harness artifact). **zh speaker ID dropped (2026-08-24)** — listen is en-only; no zh speaker model.
- **No true streaming for Parakeet TDT v2** — its "real-time" is simulated streaming (growing-buffer re-decode, sherpa-onnx #2918/#3573); true streaming needs the separate Parakeet Unified model (Phase 3). **Research (2026-08-25)**: NVIDIA's avg-WER table (HF Open ASR Leaderboard, English) — TDT v2 chunked inference collapses below ~2 s (22.83 @ 1.12 s, 69.55 @ 0.56 s), so lowering `MAX_SEGMENT_DURATION` under ~2 s costs real accuracy (the model was never trained for chunked attention); **Parakeet Unified en 0.6B** (Granary ~250 k h; `nvidia-open-model-license`, fits the weight policy; 0.6B ≤ 1B) beats TDT v2 offline (5.91 vs 6.04) and streams gracefully (7.35 @ 240 ms, 6.52 @ 560 ms — the latter ≈ TDT's offline accuracy at ~9× lower latency). Own offline + streaming modes in one model.

**Architecture** (`src/interpreter/transcribe.py`):

- `RealTimeTranscribe`: Silero VAD → ring buffer → 3 worker threads (VAD → STT → translate); `max_segment_duration` caps segments. **Adaptive stability-window re-decode** (2026-08-24, replaces per-segment transcription): each new segment re-decodes the whole window so the newest utterance gets predecessor context; once the earlier text stops changing (`_stable_prefix` — word-boundary check for en, char-prefix for CJK), the window commits to `committed_chunks` and slides forward (re-decoding the newest segment alone for a colored, consistent baseline); a `max_window_seconds` cap force-commits so cost stays bounded (window is normally tiny). **Live display runs in the terminal alternate screen buffer** (`\x1b[?1049h`, vim-style) with clear-and-reprint per update — cursor-up/erase-line redraw leaked `^[[A` sequences + blank lines into macOS Terminal scrollback. `clean=True` (dictate CLI) renders one flowing plain line with spaces between chunks (zh: space-only separation; en: `.` per chunk — SenseVoice emits no punctuation) + a final `Transcript:` block to copy after exiting the alt screen; listen keeps colored + timestamped + compute-time committed lines, a live partial, and **live translation of the current window** (`window_translation`, latest-wins stale-skip; committed chunks reuse it). `evaluate()` reports WER only for whitespace-segmented (en) text; CJK/mixed reports CER only (WER is meaningless on unsegmented zh — whole-text WER on zh inflates, same reason `_archive/benchmark_transcribe.md` scores zh with CER).
- STT = sherpa-onnx int8 only: `sensevoice` (default), `parakeet-tdt-0.6b-v2` (en-only/listen). Parakeet colors per word; SenseVoice output stays uncolored (no per-token scores in sherpa-onnx 1.13.0 — documented limitation). **SenseVoice emits English in ALL CAPS (model artifact)** — `SpeechToText.extract_text` sentence-cases it for sensevoice (live lines, final transcript, and evaluate reference all go through it); parakeet already outputs natural case and is untouched.
- Translate = `opus-mt-en-zh` (deterministic, ~1.2 s/sentence, en→zh).
- **Speaker (listen only, 2026-08-24)** — `speaker.py` `SpeakerAssigner`: WeSpeaker en extractor + an online auto-expanding registry (no enrollment; first voice = `self`, second = `other`, then `speaker N`). Loaded concurrently with VAD/STT/translator in `RealTimeTranscribe._load_models`; `_transcription_worker` **embeds the RAW segment** (~0.28 s/segment, well under cadence) and `_ingest_segment` tags each committed chunk; listen lines render `[self]` / `[other]` / `[speaker N]`, and `[?]` for **ambiguous matches**. **Relative acceptance (2026-08-24, third pass — replaces the fixed 0.74/0.84 band)**: the acceptance bar is per-cluster — a segment is tagged with the best-matching speaker when its similarity clears that cluster's own measured internal consistency (`_accept_threshold`: within `CONFIDENCE_DELTA` 0.05 of the cluster's mean member similarity, floored at `CONFIDENT_THRESHOLD` 0.84; `EARLY_CONFIDENT_THRESHOLD` 0.89 binds until the cluster has absorbed TWO members — a single-absorption mean lowered the bar too fast, 23:58). A new speaker starts below the bar minus `NEW_SPEAKER_MARGIN` 0.15 (relative — no hard 0.74 constant); in between the segment is flagged `[?]` and absorbed into **no** centroid. Why relative: the same device voice measured 0.76–0.79 vs the user's voice in one session but 0.84–0.87 in another — no fixed threshold is reliable (the fixed 0.84 band silently absorbed the second voice and drifted `self` toward it, self-reinforcing). **Gray-zone promotion**: buffered `[?]` embeddings promote to a named speaker when they form a tight cluster (≥3 segments, mean pairwise ≥ `PENDING_TIGHTNESS` 0.85 with every member ≥ `PENDING_MEMBER_TIGHTNESS` 0.80, stray outliers dropped greedily) whose mean per-segment similarity to every existing speaker stays below that speaker's own acceptance bar (a new voice must be clearly farther from a speaker than its own members typically are). A promotion **retroactively relabels** earlier `[?]` chunks **only when the chunk belongs entirely to the promoted cluster** (every covered segment's assignment is `[?]`/the new name and every pending segment is promoted — `_relabel_promoted`); a chunk that also contains another speaker's segments stays `[?]`, so one speaker's words are never shown under another's label (the 23:36 "mixes with my voice" report — the user's phrase shared a window with the review audio and was relabeled `[other]`). **Transcription text is BY CONSTRUCTION identical with/without speaker ID** (verified byte-identical on every recorded session): the assigner feeds only display tags; the re-decode window logic never consults it. **kNN "looking back" window (2026-08-25)**: a segment is scored against each speaker by its MAX cosine to that speaker's KNN_WINDOW (6) most recent member embeddings, not the centroid. Centroid averaging blends the shared mic channel and inflates cross-speaker similarity (the review voice measured 0.84–0.94 vs the primary voice's centroid in the 23:58 session but only 0.76–0.87 against its individual segments, while both voices match their own members at 0.90+); kNN preserves that margin — the self-contained version of a diarization system's "look back at recent audio to detect a speaker change" (pyannote/NeMo use trained segmentation models for this; pyannote is auth-gated, out of policy; LLM-based attribution exists but is post-hoc and can hallucinate). EARLY_CONFIDENT_THRESHOLD rose to 0.89 (kNN space runs higher than centroid space) and binds until a cluster has TWO absorbed members (a single-absorption mean lowered the bar too fast — 23:58). Promoted clusters seed mean_sim from their internal tightness so the same voice can't fragment through the guard — with the caveat that "review vs user" and "review sub-cluster vs review" share the same margin geometry (internal − distance ≈ 0.05–0.08 in both), so a second review bucket can still appear in long sessions (cosmetic: both names are the non-self voice). Speaker count is unbounded (`self`, `other`, `speaker 3`, `speaker 4`, ...) — a third/further voice promotes the same way once it accumulates ≥3 consistent gray-zone segments (validated: the 22:54 three-person test → `self`/`other`/`speaker 3`). **Window caps (2026-08-24, tightened 2026-08-25)**: `max_window_seconds` 8 s / `max_window_segments` 3 — SenseVoice re-decodes a growing buffer with drifting first words, so prefix stability can fail forever and the session would render as one never-committing line; the caps bound the display (max line ~100 chars — the "line appends too long" report) while keeping re-decode context (each committed chunk = a 2-segment context decode), and apply equally with/without speaker ID. **Slide baseline = the windowed tail (2026-08-25)**: after a commit, the newest segment's display baseline is its portion of the WINDOWED decode (the safe `_strip_prefix` tail), not a standalone re-decode — standalone decodes truncated tails ("...WHICH HAS A PU" — the "cut off in a not so nice point" report) and an empty standalone+tail combo reset the window, dropping the segment's text ("some of my speech don't append"). The standalone decode remains only as a fallback for unstable windows, and an empty baseline is kept, never reset away. The tail keeps its per-word coloring (`_strip_styled_prefix` — the "color coding broken" report came from a plain-text baseline). **Per-speaker windows (2026-08-25)**: `speaker_changed` commits the window when the newest segment's assignment differs from the current window's — a line only ever appends the RIGHT speaker's speech (the "my voice gets appended to other" report — the live window accumulated mixed speakers and its tag followed the newest segment). It's safe again because the slide baseline is the context-rich windowed tail, not a standalone decode — per-speaker commits no longer cost accuracy (CER parity holds within noise; speaker-on occasionally better). **MAX_SPEAKERS = 2 (2026-08-25)**: "just self and other" — the user's own words; the new-speaker path and gray-zone promotion refuse once two speakers are named, further distinct segments stay `[?]`. This removed the review-voice fragmentation (speaker 3/4 buckets in earlier sessions — sub-clusters of one voice share the same margin geometry as distinct voices); the user asked "will limiting speakers help", and yes: stable names, honest `[?]` beyond. All 14 recorded sessions now yield exactly `self` + `other`. **Margin rescue (2026-08-25)**: with two speakers, a segment scoring just below its best speaker's bar (within 0.03) is still accepted when it beats every other speaker by ≥ 0.08 — the primary voice's weak segments have a large margin over the second cluster (e.g. "Always get" 0.87 vs 0.77 → `self`), while the device voice's fragments measure within 0.02-0.04 of BOTH clusters and stay `[?]` (the "sometimes my own voice goes to [?]" report — 00:52 session). **New-speaker quality gate (2026-08-24)**: a segment below the winner's bar minus `NEW_SPEAKER_MARGIN` creates a speaker only when it is real speech (≥ `MIN_NEW_SPEAKER_DURATION_S` 1.0 s and ≥ `MIN_NEW_SPEAKER_RMS` 0.03) — in the 23:00 three-speaker test a near-silent blip (0.93 s, rms 0.009, cosine 0.37) had claimed the `other` slot, and rms 0.02 let a fragment claim `speaker 4` (23:08); gated blips are buffered as uncertain instead. **Promotion preserves the pending buffer's non-promoted segments** (2026-08-24) — clearing it entirely would wipe a second gray-zone voice's accumulated evidence, leaving it stuck at `[?]` for the session.
- Weights shared with the benchmark under `data/benchmark/transcribe/models/` (anonymous HF download). App form undecided — **Phase 4** decides.

**Environment**:

- Container runs: `UV_PROJECT_ENVIRONMENT=.venv-container uv run --no-sync <cmd>`; never plain `uv sync`/`uv run`. Dep pins: sherpa-onnx 1.13.0 + onnxruntime 1.24.4; **torch + torchaudio from the `pytorch-cpu` index on Linux** (PyPI wheels are CUDA and fail to dlopen on the container's CPU torch). **`sentencepiece` is a direct dep** (opus-mt's Marian tokenizer needs it — silently dropped with funasr's removal, see Phase 2). **matplotlib** is a direct dep again (audio.py plotting; also transitive via noisereduce). sherpa needs `libonnxruntime.so` on the loader path (self-healed in the harness). Container audio: libportaudio2 + pulseaudio for headless `sounddevice`; macOS: `_ensure_onnxruntime_dylib` self-heals the missing bundled onnxruntime.
- Bench assets under `data/benchmark/` (gitignored via `/data/`), grouped by task; the Phase 1 run record lives in `_archive/benchmark_transcribe.md` (moved there when Phase 2 completed). **Speaker-ID assets under `data/benchmark/speaker/`** (2026-08-24): en model + LibriSpeech dev-clean subset (14 speakers, CC-BY-4.0) + results; record in `_archive/benchmark_speaker.md`.
