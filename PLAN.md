# PLAN.md

Living plan for `interpreter`. Structure, host setup & usage: `README.md`. Agent working rules: `AGENTS.md`.

- **Scope & policy:** local models only — no cloud STT/translation and no API keys, ever. Weights must be ≤1B parameters, no CC-BY-NC-or-stricter licence, and no auth-gated download. Models are internal per-task picks, never user-facing configuration: listen/en → Parakeet Unified en 0.6B offline (sherpa-onnx int8), dictate/zh-en → SenseVoiceSmall, translate → opus-mt-en-zh, speaker ID → WeSpeaker en resnet34. whisper.cpp and Moonshine were dropped; TDT was removed once Unified won; CAM++ (EER 39%) and zh speaker ID were dropped.
- **Engine (`transcribe.py`):** Silero VAD → ring buffer → worker threads (VAD → STT → translate); `max_segment_duration` 4.0 s. Adaptive stability-window re-decode re-decodes the recent window on every segment and commits once earlier text stops changing (`_stable_prefix`), bounded by 8 s / 3 segments. `MODEL_SPECS` is the single source of truth for the product and the benchmark. Rendering is decoupled via `BaseRenderer` + immutable `TranscriptSnapshot`s (`TerminalRenderer` for the CLI alternate screen, `SnapshotStore` for the GUI); `stop()` only signals and `run()` finalizes the session files.
- **Speaker ID (`speaker.py`, listen only):** WeSpeaker embedding + online auto-expanding registry (first voice `self`, second `other`, `MAX_SPEAKERS = 2`), no enrollment; tags are display-only and never change transcription text. Acceptance is relative to each cluster's own consistency — kNN max-cosine over the 6 most recent members, floored at 0.84 (0.89 until the cluster has three members), a new speaker starts 0.15 below that bar, and a 0.03/0.08 margin rescue handles borderline matches. `[?]` segments absorb into no centroid; a tight ≥3-segment cluster (mean pairwise ≥0.85, every member ≥0.80) is promoted retroactively only when it stays below every existing speaker's bar. New speakers need ≥1.0 s and RMS ≥0.03.
- **Sessions & GUI (`app.py`):** PySide6 native window over the same engine, 150 ms QTimer polling `SnapshotStore` (no Qt code on engine threads); Stop is non-blocking. Sessions are FLAC + `.txt` + `.styled` under `data/listen/` or `data/dictate/`; the GUI can resume a session, edit its transcript with 0.8 s debounced autosave, rename all sibling files, reveal in Finder, drag to Finder, and delete to the system trash. Edits keep per-word confidence colours via `_html_to_styled`; edited/added words render white. The `.app` bundle (`scripts/make_app.sh`) is a thin launcher with the repo path baked in that logs Finder-launch failures to `~/Library/Logs/Interpreter.log`. pywebview was replaced by Qt after WKWebView compositing tripped the host's display link.
- **Paths & environment:** Python ≥3.14, `uv_build`, src-layout; `src/interpreter/__init__.py` holds `DATA_DIR` and the model-directory constants. Weights download to `data/models/` on first use with `.complete` markers; `common.ensure_onnxruntime` self-heals sherpa's onnxruntime load. Pins: sherpa-onnx 1.13.0, onnxruntime 1.24.4, PySide6 6.11.2; torch/torchaudio come from the PyTorch CPU index on Linux. The container needs `libegl1 libgl1 libxkbcommon0 libfontconfig1` for offscreen Qt and `libportaudio2` + pulseaudio for headless `sounddevice`.
- **Testing:** no `tests/` suite yet; `pyproject.toml` points pytest at `tests/` and `prek` runs it on push. Add a regression test when a bug bites a pure helper, and keep any future tests offline with synthetic audio.
- **Benchmark & records:** `benchmark/*.json` hold the tracked corpora (59 STT samples, 100 WMT19 en→zh sentences, LibriSpeech dev-clean speaker split); `benchmark_assets.py` materialises the gitignored `data/benchmark/` cache on demand. The harness reuses product registries and runs in the Linux container only — host M4 numbers are reference only. `docs/benchmark_*.md` are the source-controlled records; results JSONs under `data/benchmark/*/results/` keep superseded models as historical baselines.
- **Model verdicts:** Unified en 0.6B beats TDT at every segment cap (0.114 vs 0.163 human-ref WER at 4 s; full-set 0.126 vs 0.148); the speaker probe measured top-1 100% / EER 1.6% at 0.74 on 14 LibriSpeech speakers. Streaming exports are not real-time in the container (0.096 WER @560 ms / RTF 1.96; 0.141 @240 ms / RTF 3.69) versus the windowed engine (0.114 @4 s / RTF 0.041), so the container keeps the windowed engine and streaming stays a faster-host option.
